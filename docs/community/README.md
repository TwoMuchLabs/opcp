# Community programme

**Status: proposed (7 November 2026).** These documents put GOVERNANCE.md into practice. They do not change its commitments. Where a proposal would change GOVERNANCE.md itself, it says so, and that change needs its own pull request and the maintainers' agreement.

| Document | Purpose |
|---|---|
| [RFC process](RFC-PROCESS.md) | How a change to `spec/` or `schema/` is proposed, reviewed for 14 days, decided and recorded |
| [Contributing, step by step](ONBOARDING.md) | A first contribution for each kind of contributor, including people who don't write code |
| [External technical review](EXTERNAL-REVIEW.md) | How practitioners outside the project review the specification, and what happens to their findings |
| [Becoming a maintainer](MAINTAINERS.md) | The path from contributor to reviewer to maintainer, and back |
| [Organisational diversity roadmap](DIVERSITY.md) | The steps towards GOVERNANCE.md sections 4 and 5: no organisation with more than half the maintainers, then a neutral foundation |

Why now: OPCP asks firms not to depend on a single supplier. A project run by two people from a small number of organisations is that same dependency. An outside reviewer will check whether the project follows its own rules, and in October 2026 it did not always do so (#34).
