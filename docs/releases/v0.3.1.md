**Open Process Control Plane (OPCP)** is an open framework that lets a business keep its process logic, context and authority, while renting capabilities from any supplier. This is a draft for comment.

## Upgrade from 0.3.0

0.3.1 fixes two critical defects. Everyone on 0.3.0 should upgrade.

```bash
pip install --upgrade opcp
```

### 1. A payment or posting could happen twice (issue #27)

Take a capability with a lasting effect: class R2 or above, or the `transact` or `notify` archetype. In 0.3.0, if its supplier acted but no usable reply came back (a timeout, a dropped connection, or output the contract rejects), the control plane tried the next supplier. The effect could then happen at two suppliers, and the response would report one success.

In 0.3.1:

- **The call stops.** It returns `status: failed` and `outcome: "unknown"`, with `supplier` naming the supplier to reconcile with.
- **The budget unit is kept**, because the supplier may have used it.
- **A retry goes back to the same supplier.** A retry with the same idempotency key reaches that supplier and no other, even if the route has changed since.

Checks, extractions and other calls without a lasting effect still fail over after any error.

### 2. A swap drill could pass when the authority policy had changed

`opcp swap-drill` accepted a drill record whose authority-policy revisions differed while the record said the policy was unchanged. It also accepted a `proven` time-to-swap with no drill date. The evaluator now validates every record against the schema and checks each gate against the revisions and cases it summarises.

## Changes you may need to make

- **Adapters for effectful capabilities.** Raise `opcp.adapter.DefiniteFailure` when the supplier certainly did nothing, for example when it refused the request or the connection failed before sending. Any other exception now stops the call instead of failing over. See `docs/ADAPTERS.md`.
- **Stricter date and URI checks.** `date-time`, `time`, `uri` and `uri-reference` values are now checked on every machine. Documents with free-text timestamps, such as a swap-drill `started_at` of "yesterday", are rejected. Two small MIT-licensed dependencies are added for this.
- **`evaluate_swap(..., time_to_swap_confidence="proven")`** now raises `ValueError` without a `drill_date`. It no longer uses today's date.
- **If you can't upgrade yet**, give effectful capabilities a single candidate and no escalation supplier.

## Also in this release

- **Other runtime fixes:**
  - An authority gate that cannot decide now refuses the call as R4 and logs the refusal; the error used to escape.
  - Concurrent calls with the same idempotency key now run once.
- **Tamper-evident event log (opt-in).** `EventLog(..., chain=True)` and `opcp log verify`. See `docs/EVENT-LOG.md`.
- **Conformance fixtures any implementation can run**, in `conformance/`:
  - 15 for swap-drill records;
  - 43 for the runtime.
- **Developer guides:**
  - a 15-minute quick start with a runnable example;
  - an architecture overview;
  - an adapter guide;
  - a troubleshooting guide checked against the code.
- **Release workflow.** It can be re-run safely, and it publishes to PyPI last.

The full list is in `CHANGELOG.md`.

## Known open issues

These are specification questions under public discussion. Comments are welcome on each issue:

- **#31:** idempotency records are held in memory and lost on restart.
- **#32:** a `transact` reply with `status: failed` still returns an `ok` envelope.
- **#36:** eligibility trusts the caller's data classification, and a missing residency means no restriction.
- **#37:** the authority gate has no per-principal delegation, and R2 budgets are shared.
- **#51:** the specification text for unknown outcomes is open for review until 30 November 2026.
- **#46:** the versioning model is open for review until 21 November 2026.

## Status and limits

- **Self-assessment, not certification.** Scorecard reports are a self-assessment against a published method. References show relevance, not compliance.
- **Expect change.** The specification, swap-drill format, process-pack format and question bank will change based on feedback.
