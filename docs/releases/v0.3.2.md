**Open Process Control Plane (OPCP)** is an open framework that lets a business keep its process logic, context and authority, while renting capabilities from any supplier. This is a draft for comment.

## Upgrade from 0.3.1

0.3.2 fixes two security defects found in a second red-team review. Everyone on 0.3.1 or earlier should upgrade.

```bash
pip install --upgrade opcp
```

### 1. Undeclared fields could reach a supplier from inside arrays

The context lease sends a supplier only the fields its contract declares (spec 11.2). Inside an array with no `items` schema, an array with only `prefixItems`, or one constrained only by `contains`, the lease passed every element whole. Undeclared fields nested in those elements reached the supplier. Elements are now pruned like everything else.

### 2. Two-person approval could be one person

With two-person R4 approval on, "alice" and "Alice" (or "alice ") counted as two approvers, and an approval with a blank or invisible approver name was accepted. Identities are now compared after Unicode normalisation, case folding and whitespace collapsing, with invisible characters removed, and an approval must name its approver.

## Changes you may need to make

- **Contracts with arrays.** If a contract's input has an array without an `items` schema, its object elements now reach the supplier without their fields. Declare `items` for any array whose contents the supplier needs. The bundled catalogue is unaffected.
- **Approval callbacks** must set `by` to a real name; an empty or blank one is declined.
- **`evaluate_swap()`** requires the six revision arguments, such as `process_incumbent_revision`. The old placeholders made the "unchanged" checks hold without comparing anything.
- **Proven time-to-swap.** A drill dated after the assessment no longer counts as proven; the file is refused with a message naming the process.

## Also in this release

- **Idempotency that survives a restart or a crash.** `opcp.idempotency.FileIdempotencyStore` keeps completed responses and unresolved outcomes on disk. The control plane records a supplier that may be about to act before calling it, so a crash mid-payment cannot lead to a second posting elsewhere after a restart. See "Idempotency across restarts" in `docs/ARCHITECTURE.md`.
- **Nothing leaves the device.** The offline form, report and readout now tell the browser to block every network request, and reports run no scripts at all.
- **YAML alias bombs.** Documents that would expand past one million values are refused.
- **Conformance.** The runtime fixtures and `check_runtime` now catch a runtime that doesn't implement idempotency itself.
- **BIAN v14 mappings** for every catalogue entry, each linked to the service domain's own file at a fixed commit. The specification records which external taxonomies may be bundled.
- **Supply chain.** Every GitHub Action in CI and release is pinned to a commit, and Dependabot proposes minor updates weekly.

The full list is in `CHANGELOG.md`.

## Known open issues

These are specification questions under public discussion. Comments are welcome on each issue:

- **#51:** specification text for unknown outcomes, open for review until 30 November 2026.
- **#6:** shadow calls for swap drills, open for review until 30 November 2026.
- **#46:** the versioning model, open for review until 21 November 2026.
- **#61:** whether a call's own principal may approve it (separation of duties).
- **#62:** schema-valued `additionalProperties`, how old a proven drill may be, what R1 "notify" delivers, and drill dates in swap-drill records.
- **#31, #32, #36, #37:** durable idempotency in the specification, failed `transact` replies inside an `ok` envelope, caller-declared data classification, and per-principal delegation.

## Status and limits

- **Self-assessment, not certification.** Scorecard reports are a self-assessment against a published method. References show relevance, not compliance.
- **Expect change.** The specification, swap-drill format, process-pack format and question bank will change based on feedback.
